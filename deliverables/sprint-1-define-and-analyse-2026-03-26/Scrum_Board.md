# Scrum board

**Phase:** Define & Analyse · **Sprint 1**

The project is tracked on a **GitHub Projects** board in the
[AnomalyDetector repository](https://github.com/Guts1313/AnomalyDetector). Each
phase of the plan is one tracked issue with explicit acceptance criteria, so
feedback is given against a stable spec rather than a moving target.

## Columns

| Column | Meaning |
|---|---|
| Backlog | User stories and tasks not yet scheduled |
| To do | Scheduled for the current sprint |
| In progress | Being worked on |
| Review | Awaiting architecture review / supervisor feedback |
| Done | Merged and accepted |

## Epics (mirrors the user-story backlog)

| Epic | Theme |
|---|---|
| A | Real-time detection |
| B | Investigation & audit |
| C | Tuning & explainability |
| D | Model lifecycle |
| E | Attack / defend lab |
| F | Operations, security & compliance |

The full user-story cards (with MoSCoW priority, story points and acceptance
criteria) are in [`user-stories/`](user-stories/) and in the Sprint 2 Technical
Design Document. Workflow asynchrony: GitHub issues → pull requests → the DOT
Showroom (live demo at assessment).
